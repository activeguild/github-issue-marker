# Chrome ウェブストア 掲載情報（日本語）

Developer Dashboard の各欄にそのまま貼り付けられるよう、項目ごとにまとめています。

## ストアの掲載情報タブ

### 拡張機能名・概要

この 2 つはダッシュボードで直接編集できません。パッケージ内の `_locales/ja/messages.json` の
`name` と `description` がそのまま使われます（英語版は `_locales/en/messages.json`）。
変更したいときはそちらを直して、zip を作り直してアップロードします。

| 欄 | 現在の値 |
| --- | --- |
| 拡張機能名（最大 75 文字） | `GitHub Issue Read Marker` |
| 概要（最大 132 文字） | `GitHub Issue の本文・コメントに ✓ / × のマークやメモを付けて、読んだ箇所の目印にします。` |

### 詳細な説明

```
長い GitHub Issue を読んでいると、「どこまで読んだか」「どこが気になったか」をすぐ見失います。
GitHub Issue Read Marker は、Issue の本文やコメントの段落ごとに印とメモを付けられるようにします。

■ 段落ごとに ✓ / × とメモを付ける
段落にマウスを乗せると、左側に [✓] [×] [メモ] のツールバーが出ます。
・✓ … 読んだ・確認した箇所の目印
・× … 指摘したい・引っかかった箇所の目印
・メモ … その箇所へのコメント（あなたのブラウザー内だけに表示されます）
同じボタンをもう一度押せば解除できます。
段落・リスト項目・見出し・コードブロック・表の行・折りたたみの見出しに対応しています。

■ メモと × から返信コメントを下書きする
右クリックメニューまたはツールバーアイコンから「メモと×から返信コメントを作成」を選ぶと、
印を付けた箇所を Markdown の引用として集め、その下にあなたのメモを添えた返信文を組み立てます。
「メモがある箇所 / ×の箇所 / ✓の箇所」をチェックボックスで選べます。
リストは「-」、コードブロックはフェンス、表の行は「|」区切りで、元の形を保ったまま引用されます。
出来上がった文章は、ページ下部のコメント欄へそのまま挿入するか、クリップボードへコピーできます。

■ 付けた印は保存されます
マークとメモは Issue ごとに保存され、次に同じ Issue を開いたときに復元されます。
不要になったら「このページのマークとメモをすべて消去」でまとめて消せます。

■ プライバシー
外部への通信は一切行いません。
マークとメモはあなたのブラウザー内（chrome.storage.local）にのみ保存され、
開発者を含む誰も見ることはできません。
ソースコードはすべて GitHub で公開しています。
https://github.com/activeguild/github-issue-marker

■ ご注意
本拡張機能は GitHub, Inc. とは一切関係のない非公式ツールです。
```

## プライバシータブ

### 単一用途の説明

```
GitHub の Issue ページ上で、本文やコメントの段落に「読んだ」「気になる」の印とメモを付け、
後から見返したり返信コメントの下書きに使ったりできるようにすることが唯一の目的です。
```

### 権限の使用理由

| 権限 | 記入する理由 |
| --- | --- |
| `storage` | 利用者が付けたマークとメモを、次回同じ Issue を開いたときに復元するため、ブラウザー内に保存します。 |
| `contextMenus` | 「返信コメントを作成」「このページのマークとメモを消去」を右クリックメニューから実行できるようにするためです。 |
| `clipboardWrite` | 作成した返信コメントの文面を、利用者のクリックに応じてクリップボードへコピーするためです。 |
| ホスト権限 `https://github.com/*` | GitHub の Issue ページ上にマーク用ツールバー・メモ・返信作成パネルを表示するためです。他のサイトでは動作しません。 |
| リモートコードの使用 | 使用していません。すべてのコードが拡張機能のパッケージに含まれています。 |

### データ使用の申告

収集するデータの種類: **「ウェブサイトのコンテンツ」のみチェック**

理由は次のとおりです。

- 本拡張機能は、段落を識別するハッシュ値を作るときと、返信コメントの引用を組み立てるときに、
  ページ上の文字列を読み取ります（`content.js` の `hash()` と `quoteSource()`）。
  これは「ウェブサイトのコンテンツを扱う」に当たります
- 読み取った文字列そのものは保存しません。保存するのはハッシュ値・利用者が入力したメモ・
  Issue のパスだけで、いずれも `chrome.storage.local` にとどまり外部送信はありません

ほかの種類（個人を特定できる情報 / 健康 / 金融 / 認証情報 / 個人的な通信 / 位置情報 /
ウェブ履歴 / ユーザー行動）はチェックしません。

> **補足**: ローカル保存のみで外部送信がない場合にチェックが必要かどうかは、公式ドキュメントでは
> 明確に書かれていません。「ローカルに保存・処理する場合でも開示が必要」という記述がある一方、
> 「収集（collect）」の定義は端末外への送信を指すとも読めます。
> 審査で弾かれるリスクを避けるため、**申告しすぎる側に倒しています**。
> ソースを読めば文字列を読み取っていることは分かるので、申告しないほうがリスクが高いという判断です。
> ダッシュボードの説明文を読んで違和感があれば外してください。
>
> 「ウェブ履歴」は判断が分かれる余地があります（保存キーに `/owner/repo/issues/123` という
> パスが含まれるため）。ただしこれは利用者が印を付けたページに限られ、閲覧履歴の収集ではないので、
> チェックしない判断にしています。

下部の 3 つのチェックボックスは、いずれも該当するためチェックします。

- [x] 承認された用途以外でユーザーデータを販売または譲渡しない
- [x] アイテムの単一用途と関係のない目的でユーザーデータを使用または転送しない
- [x] 信用調査や融資目的でユーザーデータを使用または転送しない
